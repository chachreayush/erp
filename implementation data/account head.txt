# 5. The really important part: don't create everything manually

A good ERP normally has **two concepts**:

### A. System-defined accounts/groups

These are created by the software.

For example:

Assets

### B. User-created accounts

The user can create:

Commission Income
ABC Medical Store

So your system should have a distinction between:

SYSTEM
USER

for the account/group.

This becomes useful later because you don't want a user accidentally deleting something fundamental to the accounting engine.

# 9. This is where many beginner ERP designs go wrong

A poor architecture might do this:

Customer table
Sales table
Payment table
Ledger table
Outstanding table
Balance Sheet table

and keep separate balances everywhere.

That creates problems.

For example:

Customer Balance = ₹30,000

Ledger Balance = ₹28,000

Outstanding = ₹32,000

Now your ERP has conflicting numbers.

A better architecture is:

TRANSACTIONS
      ↓
ACCOUNTING ENTRIES
      ↓
GENERAL LEDGER
      ↓
REPORTS

Reports calculate/display information from the accounting data.

# 11. Groups don't actually "hold money"

This is another important concept.

Suppose:

Expenses
   ↓
Warehouse Expenses
      ↓
Loading Charges ₹40,000
Unloading ₹30,000
Transportation ₹50,000

The group:

Warehouse Expenses

doesn't necessarily have its own independent transaction.

Instead:

Loading Charges
Unloading
Transportation

have transactions.

The software **aggregates the child accounts**.

Therefore:

Warehouse Expenses
= ₹40,000
+ ₹30,000
+ ₹50,000

= ₹1,20,000

This is why hierarchical groups are so powerful.
